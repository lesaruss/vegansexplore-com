## Known quirks

- **The Supabase connector holds some writes** (`execute_sql` times out at 60 s with "the server asked the user a question").
  It held `cron.alter_job` and an `update` this session. Reads, `select net.http_post(...)` and deploys went through. The
  one-time function route worked twice (`ve-once-menu-links`, `ve-once-menu-check`, both now 410 stubs). CLAUDE.md, Database
  writes the connector holds.
- **pg_net is slow at times**: a `net.http_post` can sit in `net.http_request_queue` for a minute or two, and a response row
  can be missing on one read and present on the next. Read `net._http_response` by an id range, not a single id.
- **Functions deploy from a commit** through `ve-function-deploy` (called with `select net.http_post(...)` and the admin token
  read inside the SQL); always compare the returned `source_sha256` with `sha256sum` of the repo file. A new function gets a
  stub first through the connector with verify_jwt off, since ve-function-deploy keeps the current setting.
- This container cannot reach outside sites (restaurant pages, Toast, Square): test readers by calling the deployed function.
