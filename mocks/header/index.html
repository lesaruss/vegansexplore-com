1 · The header today

Two dozen controls before the first listing

What is stacked

  • 1 Menu bar: logo, six sections, Search, Share, Log In, Join
  • 2 Banner: title, section name, a dropdown and three buttons (Directory Home, Submit Listing, Expand)
  • 3 Sub-section tabs
  • 4 A second search box, plus Filters

What it adds up to

  • Desktop: about 24 things to read or tap before a listing, and the first card starts 40% of the way down.
  • Phone: the first card starts at 46%.
  • "Media" appears three times and "Directory" three times, all saying where you are.
  • Two search boxes, one labelled Search and one that searches only this list. A visitor cannot tell which is which.
2 · What I'd change, and why

Search is the front door. Everything else gets quieter.

Root causeEvery feature we added got its own button in the header: Search, Share, Apps, Expand, Directory Home, Submit Listing. Each was fine alone. Nobody ever set a budget for the top of the page, so it only grows.
The rule: a chrome budgetDesktop top bar: five things at most. Phone: three. Banner art belongs on the home page and city pages. Inside the site, one line says where you are.
Search says what it doesA wide labelled box in the same place on every page, with an example in it ("vegan pizza in Atlanta"), so a visitor knows they can search for anything.
Where today's buttons goShare and Submit Listing: the one-line page bar. Apps: the account menu. Expand: gone with the banner. Directory Home and the section dropdown: the breadcrumb.
The two-searches problemOne box on top that searches everything. On a list page it carries a chip, "in Documentaries & Films ✕", so the same box narrows to the list. No second box competing (slide 6).
About the inspirationI could not open PETA, VegNews or HappyCow from this build environment (the connection is blocked), so these mocks do not copy them. The pattern I'm taking from that kind of site: a short top menu with one clear search entry beside it. Drop screenshots in and I'll fold them in.
3 · Option A My pick

The search bar is the header

Wins

  • You cannot miss it: the biggest thing in the header is a search box that gives an example.
  • Menu stays visible on desktop, so nothing we already built gets harder to find.
  • Join stays on screen on a phone, so the conversion path is untouched.
  • The first card moves up about 95 px on desktop and about 140 px on a phone.

Costs

  • The header is still two rows on desktop (search, then menu).
  • The banner art goes from inner pages. The chapter's photo stays on the home page and city pages.
  • Phone is two rows too, one more than option C.
4 · Option B

One slim row, search that grows when you use it

Wins

  • Lightest desktop: one 64 px row, then the page.
  • The chapter art stays, so the site keeps its look.
  • On a phone, search takes over the whole screen when tapped, so it has room to show suggestions.

Costs

  • On desktop the search box is 300 px wide and shares the row with six links. It is easier to miss than A.
  • On a phone search is an icon, the weakest signal that you can search for anything.
  • Still a banner on inner pages, the thing Josh's feedback points at.
5 · Option C

Almost nothing: logo, search, Menu

Wins

  • The cleanest. Search is the header, with nothing beside it competing.
  • One row on a phone, so the page starts 60 px down.
  • The Menu panel can explain each section in a line, which helps a first-timer.

Costs

  • Every section is a click deeper. A visitor can no longer see what the site contains at a glance.
  • On a phone Join moves into the menu. That is a real cost to the Founding Member push before January 1.
  • The wordmark shrinks to the mark on a phone.
  • I left out bottom tab bars: you said no bottom bar on 11-01.
6 · Works with every option

One box. On a list it carries a scope.

How it works

  • On the home page, a city page, a Guide or anywhere else: no chip, the box searches everything.
  • On a list, such as Documentaries or Events: the box opens with a chip for that list, so people searching inside a list find it where they expect to.
  • The ✕ on the chip, or the "Search everything" row, widens it. This is how Amazon and Airbnb handle it.
  • The in-page "Filter this list…" box stays, but it is a filter, not a search, so it no longer competes.

Not decided

  • Whether results show as a dropdown (as drawn) or a full page. The dropdown is faster. The full page is what the engine has now.
